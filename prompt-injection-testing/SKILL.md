# 提示注入测试

## 何时使用

- 用户提供系统 Prompt、工具权限或信任边界，需要生成**可执行的注入攻击测试用例**。
- 需要验证 LLM 应用抵抗直接/间接注入、数据外泄、越权工具使用的能力。

## 输入要求

| 必填 | 字段 | 说明 |
|------|------|------|
| ✅ | 系统 Prompt | 被测应用的完整系统提示词 |
| ✅ | 可用工具 | Agent 可调用的工具列表及权限 |
| ⬜ | 信任边界 | 用户输入与系统指令的隔离方式 |
| ⬜ | 检索源 | RAG 文档或外部数据源（间接注入面） |
| ⬜ | 敏感资产 | 不应被泄露的数据、密钥、内部信息 |

## 执行流程

### 1. 输入审计

- 检查系统 Prompt 是否完整
- 检查工具权限是否明确（哪些操作需要审批）
- 缺失信息标记为「假设」

### 2. 威胁建模

识别注入攻击面：

| 攻击类型 | 描述 | 风险等级 |
|----------|------|---------|
| 直接注入 | 用户在输入中嵌入覆盖系统指令的文本 | P0 |
| 间接注入 | 通过检索文档/网页/邮件注入恶意指令 | P0 |
| 指令层级混淆 | 试图让模型混淆 system/user/tool 消息 | P1 |
| 数据外泄 | 诱导模型输出系统 Prompt 或敏感数据 | P0 |
| 工具越权 | 诱导模型调用未授权的工具或参数 | P0 |
| 编码混淆 | Base64/Unicode/ROT13 等编码绕过过滤 | P1 |
| 多轮持久化 | 通过多轮对话逐步建立恶意上下文 | P1 |

### 3. 攻击用例生成

为每种攻击类型生成具体测试用例，格式：

```markdown
## [P0] INJ-<类型>-<序号>: <攻击标题>
[攻击类型] 直接注入
[攻击载荷] <具体的注入文本>
[注入位置] 用户输入 / 系统 Prompt / 检索文档
[预期行为] 1. 模型拒绝执行 2. 不泄露系统 Prompt 3. 不调用未授权工具
[预期输出] <拒绝回复的判定标准>
[通过标准] <具体判定条件>
[影响等级] 高 / 中 / 低
```

### 4. 用例校验

生成后必须执行以下校验：

- [ ] 每种攻击类型至少有 2 条用例（直接 + 间接/变体）
- [ ] 攻击载荷具体可执行（非泛泛描述）
- [ ] 预期行为明确（拒绝/忽略/降级，有判定标准）
- [ ] 至少覆盖 1 条数据外泄测试
- [ ] 至少覆盖 1 条工具越权测试
- [ ] 所有载荷使用占位数据，不含真实敏感信息

### 5. 输出交付物

| 文件 | 内容 |
|------|------|
| `attack-suite.md` | 完整攻击测试用例集（含威胁模型、载荷、预期行为） |
| `run-attacks.py` | 可执行的批量测试脚本（逐条发送载荷 + 记录响应） |

## 核心约束

- **仅在授权环境使用**，所有载荷使用安全占位数据。
- 不提供可用于真实攻击的敏感目标或完整利用链。
- 验证拒绝后是否仍有副作用（如日志泄露、工具被调用）。
- 保持防守和评审导向，不写成进攻式操作教程。

## 参考文件

- `prompts/prompt-injection-testing.md`：详细执行规范。
- `evals/eval.yaml` + `evals/cases/`：评估用例模板。

## 常见误区

- 只测一种注入方式 → 需要覆盖直接/间接/编码/多轮等多种类型。
- 只看模型是否拒绝 → 需要验证拒绝后无副作用。
- 用真实数据测试 → 必须使用占位数据。
- 跳过间接注入 → RAG/文档/邮件是常见攻击面。

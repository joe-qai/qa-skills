# 接口测试用例设计标准

基于接口文档生成结构化测试用例时，遵循以下标准。

## 覆盖维度

对每个接口，至少覆盖：

1. **正向用例**：合法参数，验证成功响应（状态码、关键字段、数据写入）
2. **参数缺失**：必填参数逐一缺失，验证错误码与提示
3. **参数越界**：长度、范围、格式非法，验证校验逻辑
4. **鉴权异常**：无 token / 过期 token / 错误 token，验证 401/403
5. **幂等性**：重复提交，验证是否产生副作用
6. **并发冲突**：多请求同时操作同一资源，验证锁或冲突提示

## 字段要求

每条用例必须包含：

- **用例标识**：`API-[模块]-[序号]`（如 `API-LOGIN-001`）
- **接口路径与方法**：`POST /api/v1/login`
- **用例类型**：正向 / 参数缺失 / 参数越界 / 鉴权异常 / 幂等 / 并发
- **优先级**：P0（核心正向）/ P1（基本校验）/ P2（边界异常）/ P3（低频场景）
- **前置条件**：数据准备、环境要求
- **请求参数**：JSON body / query / path 参数
- **预期结果**：状态码、响应体关键字段、数据库变更
- **备注**：关联接口、数据依赖

## 输出格式示例

```markdown
## [P0] 登录成功 - 用户名密码
[测试类型] 正向
[接口] POST /api/v1/login
[前置条件] 用户 test_user 已注册且未锁定
[请求参数] {"username": "test_user", "password": "Valid@123"}
[预期结果] 1. 状态码 200。2. 返回 token 和 user_id。3. 不返回 password 字段。
```

# 功能测试用例设计标准

基于 PRD / 需求文档生成功能测试用例时，遵循以下标准。

## 覆盖维度

对每个功能模块，至少覆盖：

1. **核心正向流程**：用户完成主要目标的 happy path
2. **分支流程**：次要路径、可选步骤、不同入口
3. **输入校验**：必填、格式、长度、特殊字符、SQL 注入
4. **状态流转**：正常流转、非法跳转、回退、终态
5. **权限控制**：不同角色的可见性与操作范围
6. **边界条件**：空值、极值、并发操作

## 字段要求

每条用例必须包含：

- **用例标识**：`FUNC-[模块]-[序号]`（如 `FUNC-LOGIN-001`）
- **功能模块**：所属业务模块
- **用例类型**：正向 / 反向 / 边界 / 状态流转 / 权限
- **优先级**：P0（核心正向）/ P1（基本校验）/ P2（边界异常）/ P3（低频场景）
- **前置条件**：数据准备、登录状态、环境要求
- **测试步骤**：编号步骤，每步一个操作
- **预期结果**：与步骤对应的预期行为

## 输出格式示例

```markdown
## [P0] 用户登录成功
[测试类型] 正向
[前置条件] 用户已注册，账号未锁定
[测试步骤] 1. 打开登录页面。2. 输入用户名 test_user。3. 输入正确密码。4. 点击登录按钮。
[预期结果] 1. 页面跳转到首页。2. 显示用户信息。3. 不返回密码相关字段。
```

# 自动化候选用例标准

筛选和标记适合自动化回归的测试用例时，遵循以下标准。

## 候选条件

适合自动化的用例应满足：

1. **高频执行**：每次发布必跑的回归用例
2. **稳定可靠**：结果确定、不依赖人工判断
3. **步骤明确**：操作步骤可程序化描述
4. **数据可构造**：测试数据可脚本生成或预置
5. **环境可控**：不依赖特殊硬件或人工审批

## 不适合自动化的用例

- 探索性测试、可用性测试、主观评估类
- 依赖物理设备交互（如 NFC 碰一碰）
- 需要人工审批流的端到端场景
- 频繁变更的 UI 布局验证

## 标记字段

在用例基础上追加：

- **自动化候选**：是 / 否 / 待定
- **自动化类型**：API 自动化 / UI 自动化 / 混合
- **预计收益**：高频回归 / 冒烟测试 / 全量回归
- **前置依赖**：需要的测试框架、数据构造脚本、环境配置

## 输出格式示例

```markdown
## [P0] 登录成功 - 用户名密码
[测试类型] 正向
[自动化候选] 是
[自动化类型] API 自动化
[预计收益] 高频回归（每次发布必跑）
[前置依赖] pytest + requests，测试用户数据 fixtures
```
